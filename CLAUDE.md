Rules:
- Run `pnpm arch:check` after every completed task.

- Fix architectural violations in code before finishing; do not weaken rules to pass.
- Add a failing test first (TDD) for any behavior change.

## Architecture Rules (arch-contract)

> Generated by ArchContract from `arch-contract.yaml`. Do not edit between the markers — run `arch-contract sync-agent-rules` to regenerate. Generated code MUST follow these rules; `pnpm arch:check` will fail on any violation.

### Layers — where code lives
Every source file belongs to exactly one layer, decided by its path:
- **core** — `packages/arch-contract/src/core/**/*.ts`
- **config** — `packages/arch-contract/src/config/**/*.ts`
- **project** — `packages/arch-contract/src/project/**/*.ts`
- **parser** — `packages/arch-contract/src/parser/**/*.ts`
- **graph** — `packages/arch-contract/src/graph/**/*.ts`
- **rules** — `packages/arch-contract/src/rules/**/*.ts`
- **reporters** — `packages/arch-contract/src/reporters/**/*.ts`
- **baseline** — `packages/arch-contract/src/baseline/**/*.ts`
- **agents** — `packages/arch-contract/src/agents/**/*.ts`
- **cli** — `packages/arch-contract/src/cli/**/*.ts`

### Module boundaries
- Modules live at `src/modules/*`. Import across modules only through the module's public API file `index.ts` — never reach into a module's internals.

### Import rules
- **no-cycles**: No dependency cycles between files.

### Naming & code conventions
- **reporters-stay-pure** — the `reporters` layer:
  - must not depend on npm packages: `ts-morph`

### Adding a new file — checklist
1. Pick the layer it belongs to and put it under that layer's path (see "Layers").
2. Follow the naming convention for that layer (suffixes from "Naming & code conventions").
3. Only import from layers this layer may depend on (see "Allowed dependencies").
4. Cross-module imports go through `index.ts` only.

### Before you finish
Run `pnpm arch:check` and fix every violation in code.
Do not weaken or delete rules to make it pass.
